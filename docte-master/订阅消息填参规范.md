## 2. 各业务场景标准填参

| 业务场景 | 标准填充值 |
| --- | --- |
| 报修提交 `repair_submitted` | `thing1`=设备型号，缺失时取设备名称；`character_string2`=工单号；`phrase3`=`已受理`；`thing4`=`报修已受理，请留意后续进度` |
| 设备签收 `order_received` | `character_string1`=工单号；`thing3`=维修仓库地址，缺失时为`佛山市南海区罗村新光源基地B5座五楼`；`character_string6`=客户寄修物流单号；`thing5`=`设备已确认入库`或触发方备注 |
| 维修报价 `quote_issued` | `thing1`=`维修报价已出具，请核对费用后付款`；`thing2`=设备型号；`date3`=报价生成时间；`amount4`=维修总价，如`1280.50元`；`character_string5`=工单号 |
| 付款成功 `payment_confirmed` | `thing1`=`款项已核验到账，将启动维修`；`thing2`=设备型号；`date3`=到账/核销时间；`amount4`=维修总价；`character_string5`=工单号 |
| 付款驳回 `payment_rejected` | `thing1`=`付款审核未通过，请重新核对支付`；其余字段与付款成功一致；日志仍记录独立业务类型 `payment_rejected` |
| 进度提醒 `process_tip` | `character_string1`=设备型号；`character_string2`=设备 SN；`thing3`=当前处理进程。此模板当前仅保留授权，主流程没有主动推送分支 |
| 回寄发货 `order_shipped` | `character_string1`=工单号；`thing3`=诊所收件地址；`character_string6`=维修回寄物流单号；`thing5`=`维修设备已回寄`或触发方备注 |
| 工单完成 `order_completed` | `character_string1`=工单号；`thing3`=设备型号；`thing4`=维修结果摘要 + 发票状态提示。已开具时显示`发票已开具，请到工单查看`，待开票时显示`发票开具后，请到工单查看`；已确认到账的微信支付订单可提示客户申请发票 |

## 3. 字段限制

- `thing` 最长 20 个字符，云函数统一截断；完工消息会为发票提示预留长度。
- `character_string` 最长 32 个字符，只保留数字、字母和常用符号；工单号、物流单号、设备型号和 SN 应优先使用英文数字格式。
- `phrase3` 固定为 `已受理`，不超过 5 个汉字。
- `date3` 格式固定为 `YYYY-MM-DD HH:mm:ss`。
- `amount4` 格式固定为两位小数加`元`，例如 `1280.50元`。
- 微信官方 `wx.requestSubscribeMessage` 当前单次最多接收 5 个模板 ID；前端对 ID 去重并限制为 5 个，且当前 5 套模板标题互不重复。

## 4. 不再推送的场景

`inspection_completed`、`repair_started`、`review_invite`、`invoice_issued` 不调用订阅消息接口。发票信息只随 `order_completed` 一次性告知。

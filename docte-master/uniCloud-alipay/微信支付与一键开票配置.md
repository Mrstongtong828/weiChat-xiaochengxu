# 微信支付 + 一键开票（微信电子发票/服务商）上线配置清单

> 方案：**微信支付收款 → 财务确认到账 → 后台「一键开票」→ 开票服务商自动开票 + 回填链接/号码/日期 + 推微信电子发票卡包**。
> 电子税务局手动开票（上传/回填）保留作专票/红冲/特殊抬头的兜底。

---

## 一、微信支付（前提，必须先打通）

微信电子发票挂在微信支付上，所以**先把微信支付配好**。支付逻辑在 `cicada-client-order`（下单/JSAPI 支付）和 `cicada-admin-order`（退款/核销）两个云函数。

### 当前实现和接口边界

本项目使用 uni-app 的 `uni.requestPayment` 拉起微信收银台，云端由现有云对象直接接入微信支付 API v3；当前**没有使用 `uni-pay`**。

| 组件 | 接口或模块 | 边界 |
|---|---|---|
| 小程序维修详情页 | `uni.requestPayment` | 只接收云函数返回的支付参数并拉起收银台 |
| `api/repair.js` | `createRepairWechatPay` / `syncRepairWechatPay` | 转发工单 ID，不传入或计算支付金额 |
| `cicada-client-order` | `createWechatPayPayment` / `wechatPayNotify` / `syncWechatPayPayment` | 服务端读取报价金额、调用 API v3、签名、验签解密、查单并更新到账状态 |
| `cicada-admin-order` | 退款和核销方法 | 处理退款、线下转账及财务对账 |

```text
创建预支付单 -> uni.requestPayment -> 微信异步通知/服务端主动查单 -> 确认到账
```

必须遵守以下边界：

- `uni.requestPayment` 的 `success` 不是到账凭证，不能直接写 `payment_status=paid`。
- `payment_status=paid` 只能由服务端验签回调或向微信查单确认后写入。
- 商户私钥、APIv3 密钥、微信支付公钥等 `WX_PAY_*` 配置只能放在云函数环境变量中，禁止进入小程序代码或仓库。
- `uni-pay` 是可选的完整支付模块，不是 `uni.requestPayment` 的替代名称。迁移 `uni-pay` 需要重新设计下单、回调、查单、退款和工单状态对接；当前上线范围不包含该迁移。

### 1. 微信支付商户平台要做的
- 开通 **JSAPI 支付**（小程序支付）
- 关联小程序 AppID：`wx25289fbe4a3bf011`
- 申请/下载 **商户 API 证书**（apiclient_cert.pem / apiclient_key.pem），记下 **证书序列号**
- 下载 **微信支付公钥**，记下公钥 ID（当前：`PUB_KEY_ID_0117477337352026072200382178004605`）
- 设置 **APIv3 密钥**
- 配置支付结果回调 URL（指向云函数 URL 化地址）

### 2. 云函数环境变量（`cicada-client-order` + `cicada-admin-order` 都要配）
| 环境变量 | 说明 |
|---|---|
| `WX_PAY_APPID`（或 `WX_APPID`） | 小程序 AppID `wx25289fbe4a3bf011` |
| `WX_PAY_MCH_ID` | 微信支付商户号 |
| `WX_PAY_SERIAL_NO` | 商户 API 证书序列号 |
| `WX_PAY_PRIVATE_KEY`（或 `WX_PAY_PRIVATE_KEY_BASE64`） | 商户 API 私钥（apiclient_key.pem 内容；BASE64 版更稳，避免换行丢失） |
| `WX_PAY_API_V3_KEY` | APIv3 密钥 |
| `WX_PAY_PUBLIC_KEY_ID` | 微信支付公钥 ID `PUB_KEY_ID_0117477337352026072200382178004605` |
| `WX_PAY_PUBLIC_KEY`（或 `WX_PAY_PUBLIC_KEY_BASE64`） | 下载的微信支付公钥 PEM；用于响应和通知验签 |
| `WX_PAY_NOTIFY_URL` | 仅 `cicada-client-order` 配置：`https://env-00jy6g4qwi94.dev-hz.cloudbasefunction.cn/cicada-client-order/wechatPayNotify` |
| `WX_PAY_REFUND_NOTIFY_URL` | 仅在实现独立退款通知处理器后给 `cicada-admin-order` 配置；不得复用支付回调地址 |

> `WX_PAY_SERIAL_NO` 是商户 API 证书序列号，不能填写 `PUB_KEY_ID_*`。缺任一项，云函数会抛明确配置错误。配置位置：uniCloud 控制台 → 对应云函数 → 环境变量。
>
> uniCloud 单个环境变量值最多 1024 字符。私钥 Base64 超限时，不配置单值 `WX_PAY_PRIVATE_KEY_BASE64`，而是按原顺序连续拆成 `WX_PAY_PRIVATE_KEY_BASE64_1`、`WX_PAY_PRIVATE_KEY_BASE64_2`、`WX_PAY_PRIVATE_KEY_BASE64_3`（每段不超过 1024 字符）。代码会自动拼接，中间不能缺段。微信支付公钥超限时可同样使用 `WX_PAY_PUBLIC_KEY_BASE64_1`、`_2`、`_3`。

### 3. 验证
- 部署前运行支付相关测试：`node --test uniCloud-alipay/cloudfunctions/common/cicada-wechat-pay-crypto/index.test.js uniCloud-alipay/cloudfunctions/common/cicada-payment-proof/index.test.js`
- 构建小程序：在 `docte-master/` 运行 `npm run check`。
- 使用真机发起一笔可留档的小额支付，确认能够拉起微信收银台。
- 支付完成后检查微信商户单号、云函数回调/查单日志及 `cicada_orders.payment_status`；只有服务端确认后才应为 `paid`。
- 至少验证一次用户取消支付，确认工单不会被误写为 `paid`。

## 二、微信电子发票（客户侧渠道）

- 微信支付商户平台 → **开通「微信电子发票」**
- 实际开票由**开票服务商**完成（微信只负责把开好的票推到客户卡包/给链接）

## 三、开票服务商（实际开票的 API）

选并签约一个支持微信电子发票的服务商（**诺诺/百望/高灯**等），拿到 API 凭证。

### 1. 服务商/财务要提供
- API 文档 + `appKey/appSecret/接口地址`（**测试 + 正式**两套）+ 沙箱环境
- 销方信息：公司全称、纳税人识别号、地址电话、开户行账号
- **商品税收分类编码**（维修服务对应编码）+ **税率**（6% 或 13%，以税务核定）

### 2. 云函数环境变量（`cicada-admin-order`）
| 环境变量 | 说明 |
|---|---|
| `INVOICE_PROVIDER` | 服务商标识，如 `nuonuo` / `baiwang` |
| `INVOICE_PROVIDER_APP_KEY` | 服务商 appKey |
| `INVOICE_PROVIDER_APP_SECRET` | 服务商 appSecret |
| `INVOICE_PROVIDER_API_BASE` | 服务商接口地址 |
| `INVOICE_SELLER_TAX_NO` | 销方税号 |
| `INVOICE_TAX_CODE` | 商品税收分类编码 |
| `INVOICE_TAX_RATE` | 税率，如 `0.06` |
| `INVOICE_PUSH_WECHAT` | `1` = 同时推送微信电子发票卡包 |

### 3. 代码接入点（开发对接处，已搭好骨架）
- `cicada-admin-order/index.obj.js` → **`callInvoiceProvider(req)`**：按服务商文档实现「下单开票 + 查结果（拿版式文件URL/号码/日期）+（可选）微信卡包推送」，返回 `{ invoice_no, invoice_date, invoice_url }`。
- 其余闭环已就绪：`issueInvoice` 方法、后台「一键开票」按钮、回填 `invoice_info`、客户端「已开票」展示与复制下载。
- 未配置时「一键开票」会明确提示「开票服务商未配置」，不会误判成功。

## 四、一键开票流程（已实现的业务规则）

```
客户在小程序填抬头/税号/邮箱申请开票
  → 财务确认到账（payment_status = paid）   ← ⭐ 强制前置：未到账不允许开票
  → 后台工单抽屉「发票登记」点【一键开票】
  → issueInvoice 校验(有申请/未开过/已到账/有抬头税号/金额>0)
  → callInvoiceProvider 调服务商开票、取号码/日期/链接
  → 回填 invoice_info(已开具) + 记审计日志 + 通知客户
  → 小程序「已开票」显示号码/日期、可复制链接下载
```

> 校验位置：`cicada-admin-order.issueInvoice`。到账判断：`order.payment_status === 'paid'`。

## 五、部署清单
1. 配好 **微信支付** `WX_PAY_*`（client-order + admin-order）→ 重新部署这两个云函数
2. 运行 `npm run check`，上传新的微信小程序构建版本
3. 微信支付商户平台**开通微信电子发票**
4. 签服务商，配 `INVOICE_PROVIDER_*`，在 `callInvoiceProvider` 内实现其 API
5. 重新部署 `cicada-admin-order`、重发 PC 后台 `dist`
6. 验证：报修→报价→支付→确认到账→一键开票→小程序已开票可下载

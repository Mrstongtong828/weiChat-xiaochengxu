# 微信支付 + 对公转账人工开票配置

> 当前业务规则：**已完成结单且付款已确认的微信支付或对公转账订单均可申请发票，由财务在电子税务局人工开具，再到后台登记发票结果。**
>
> 文件名为兼容仓库既有链接暂不修改；系统不提供“一键开票”或第三方服务商自动开票。

## 一、微信支付

支付逻辑在 `cicada-client-order`（下单、JSAPI 支付、回调、查单）和 `cicada-admin-order`（退款、人工对账）两个云函数。本项目使用 `uni.requestPayment`，没有使用 `uni-pay`。

```text
创建预支付单 -> uni.requestPayment -> 微信异步通知/服务端主动查单 -> 确认到账 -> 后续维修
```

必须遵守：

- 客户端支付成功回调不是到账凭证，不能直接写 `payment_status=paid`。
- 只有服务端验签回调或微信查单成功后才能确认到账。
- 微信支付订单的 `payment_method=wechat_pay`；只有服务端确认 `payment_status=paid` 且工单已完成后才显示开票申请并允许后台登记。
- 商户私钥、APIv3 密钥和支付公钥只能放在云函数环境变量中。

### 微信支付环境变量

| 环境变量 | 说明 |
|---|---|
| `WX_APPID` | 小程序 AppID `wx25289fbe4a3bf011`，用于支付前解析当前微信账号 openid |
| `WX_SECRET` | 小程序 AppSecret，用于支付前调用 `jscode2session`，只能配置在云函数环境变量 |
| `WX_PAY_APPID`（或 `WX_APPID`） | 小程序 AppID `wx25289fbe4a3bf011` |
| `WX_PAY_MCH_ID` | 微信支付商户号 |
| `WX_PAY_SERIAL_NO` | 商户 API 证书序列号 |
| `WX_PAY_PRIVATE_KEY`（或分段 Base64） | 商户 API 私钥 |
| `WX_PAY_API_V3_KEY` | APIv3 密钥 |
| `WX_PAY_PUBLIC_KEY_ID` | 微信支付公钥 ID |
| `WX_PAY_PUBLIC_KEY`（或分段 Base64） | 微信支付公钥 PEM |
| `WX_PAY_NOTIFY_URL` | `cicada-client-order/wechatPayNotify` URL 化地址 |

uniCloud 单个环境变量值最多 1024 字符。Base64 超限时按顺序拆为 `_1`、`_2`、`_3`，中间不能缺段。

`WX_APPID` 必须与 `WX_PAY_APPID` 一致。小程序每次创建预支付单前会获取新的微信临时 code，云函数用它解析本次付款人 openid；只有付款人、金额和有效期均相同时才会复用已有 `prepay_id`。

## 二、对公收款账户

后台“系统设置 -> 联系与公众号 -> 对公转账账户”维护以下字段；工单收款页、结算管理页和客户转账弹窗读取同一配置：

| 字段 | 当前值 |
|---|---|
| 户名 | 佛山市登煌医疗器械有限公司 |
| 开户行 | 中国农业银行佛山惠景支行 |
| 账号 | 4442 3201 0400 04288 |

客户转账时必须备注工单编号。客户上传凭证后，订单写入：

- `payment_method=offline_transfer`
- `payment_status=uploaded`

财务同步核对银行流水后在后台点击“审核通过”，订单才变为 `payment_status=paid`。

### 后台确认到账并转入下一工序

1. 使用 `finance`、`admin` 或 `superadmin` 角色登录 PC 后台。
2. 进入“报修工单管理”，打开对应工单，切换到“收款”页签。
3. 对照银行对公流水核验收款账户、金额和工单编号备注；客户上传的截图只能作为辅助材料，不能代替银行流水。
4. 确认无误后点击“审核通过”，并在二次确认框中再次确认。
5. 后端写入 `payment_status=paid`、`payment_paid_time` 和审计记录；工单当前状态允许时会自动进入“处理中”，不需要再手工重复推进。
6. 如果页面提示配件未自动出库，付款确认仍然有效，需立即到“库存管理”核对并处理出库异常。

注意事项：

- 微信支付由支付回调或服务端查单自动确认，后台禁止手工标记到账。
- 银行流水不匹配时点击“驳回”，填写原因，等待客户重新提交凭证。
- 提交时如果提示“工单状态已变化”，先刷新工单再重新核对，避免覆盖其他后台人员的处理结果。

## 三、人工开票流程

```text
客户完成微信支付，或选择对公转账并由财务确认到账
  -> 检修服务交付并完成结单
  -> 客户提交开票资料
  -> 财务在电子税务局人工开具
  -> 后台工单“发票”页登记状态、号码、日期，可选上传电子票原件到项目云存储归档
  -> 客户在小程序查看已开票结果
```

统一校验位于 `common/cicada-invoice-policy`：

- 付款方式必须为 `wechat_pay`、`offline_transfer` 或兼容旧值 `bank_transfer`。
- 工单状态必须为 `completed`。
- 付款状态必须已确认。
- 开票金额必须大于零。
- 微信支付订单必须由服务端回调验签或主动查单确认到账，不能依赖客户端成功回调取得开票资格。
- 税收分类固定为“修理修配劳务”，发票项目固定为“牙科设备检修服务费”。
- 一个发票号码只能绑定一个检修订单；手工登记和批量导入都会拒绝重复号码。
- 订单、工单记录和发票记录必须一一对应，禁止脱离工单单独登记发票。

后台只保留 `updateInvoiceStatus` 人工登记接口；不存在 `issueInvoice`、自动开票按钮或 `INVOICE_PROVIDER_*` 配置。

### 财务登记与交付

1. 在“报修工单管理”打开符合条件的工单，切换到“发票”页签。
2. 核对客户提交的抬头、税号及专票资料，在电子税务局或金税系统中人工开具。
3. 电子普通发票预计 1-3 个工作日开具；纸质专用发票预计 7-15 个工作日寄出。
4. 开具完成后登记“已开具”、发票号码、开票日期和金额。纸质专票寄出后继续登记快递公司、快递单号和“已寄出”状态。
5. 电子票原件只能上传到本项目云存储，不得填写不受控的外部 PDF 地址。上传并登记“已开具”后，系统向对应订单客户提供小程序查看和下载。
6. 保存后使用对应订单客户账号在小程序核对结构化发票摘要，并验证 PDF 可正常下载、打开和通过微信菜单保存或分享。

### 小程序展示方式

- 财务登记“已开具”时填写发票抬头、发票号码、开票日期和金额，小程序直接展示这些结构化信息。
- 用户可在“发票与开票 -> 已开票”查看并一键复制发票信息；后台已上传项目云存储 PDF 时，可点击“查看/下载发票”打开原件，并通过微信文档菜单保存或分享。
- 已开具但尚未上传 PDF 时，小程序显示“发票原件待上传”且不可点击；PDF 仅向对应订单的已登录客户开放，其他账号不得访问。
- 只有存在符合条件的微信支付/对公订单、处理中发票或历史已开发票时，小程序才展示“发票与开票”入口。

## 四、上线验证

1. 运行共享策略测试：`node --test uniCloud-alipay/cloudfunctions/common/cicada-invoice-policy/index.test.js`。
2. 在 `docte-master/` 运行 `npm run check`。
3. 验证微信支付由服务端确认到账且工单完成后，小程序可申请发票，后台可登记发票；未确认到账时不可申请。
4. 验证对公转账上传凭证后进入“待核销”，未核销时不能申请开票。
5. 财务确认到账但工单未完成时，验证客户端和后台仍不能申请或登记发票。
6. 微信支付或对公转账工单完成结单且付款确认后，验证客户可提交资料、后台可人工登记发票结果。
7. 登记测试发票号码、日期和抬头并上传项目云存储 PDF，验证对应客户可在小程序查看、复制完整发票信息，并查看/下载 PDF；未上传时显示待上传。
8. 使用另一客户账号访问，验证不能看到该订单的发票信息，也不能取得其 PDF 地址或临时下载链接。
9. 尝试给另一工单登记相同发票号码，确认后台拒绝保存或批量导入。
10. 验证户名、开户行、账号在系统设置、工单收款和结算管理中保持一致。

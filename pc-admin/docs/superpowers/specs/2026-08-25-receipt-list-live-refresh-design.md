# 配件签收后工单列表即时刷新设计

## 背景

PC 管理后台在工单详情抽屉完成配件签收和工单入库后，数据库中的工单状态已经从 `sent` 更新为 `received`，详情抽屉也显示“已签收”。但紧接着执行的列表刷新可能暂时返回写入前的旧行，当前页面会无条件用该响应替换本地列表，导致列表重新显示“运输中”。浏览器稍后刷新会重新读取到最新数据，因此状态才恢复正常。

只读排查确认：

- `cicada-admin-order.getAdminOrderList` 每次直接查询 `cicada_orders`，没有应用级列表缓存。
- `confirmInboundArrival` 和 `updateOrderStatus` 成功后会返回写入后的工单快照。
- `pc-admin/src/views/WorkOrder.vue` 会先应用该成功快照，再调用 `loadOrders()`；`loadOrders()` 当前无条件替换整个 `orders` 数组，可能用短暂旧读或较早请求的旧结果覆盖成功快照。

因此本次不修改列表云函数、数据库或共享状态机，修复 PC 页面在签收流程中的旧响应覆盖问题。

## 目标

后台人员在运输中工单的详情抽屉完成配件签收后：

1. 详情抽屉立即显示配件已确认签收、签收人和签收时间。
2. 工单主状态成功推进为 `received` 后，列表中的同一工单立即显示“已签收”。
3. 关闭详情抽屉返回列表时不需要刷新浏览器。
4. 列表接口第一次短暂返回 `sent` 时，不得把刚成功的 `received` 快照回退为“运输中”。

## 范围

### 允许修改

- `pc-admin/src/views/WorkOrder.vue`
- PC 后台专属的定向检查脚本、本地 mock、测试说明和截图产物目录
- 为注册定向检查所需的 `pc-admin/package.json`

### 禁止修改

- 小程序前端及其构建配置
- 客户端云函数、后台云函数和共享业务逻辑
- 数据库结构、索引和线上数据
- 报价、备注、维修记录、发票、回寄等其他操作的刷新行为
- 现有接口参数、响应字段、权限和状态流转规则

## 方案

### 签收快照保护

为 `loadOrders` 增加一个只在调用方显式传入时生效的“保留工单快照”选项。默认调用路径保持现有行为；只有 `confirmCurrentReceivedParts` 在状态同步成功后刷新列表时传入服务端返回的最新工单快照。

列表响应转换完成后，按以下规则处理目标工单：

1. 如果目标工单不在列表响应中，不主动插入。这样当当前筛选为“运输中”时，状态变为“已签收”的工单会自然离开结果集。
2. 如果目标工单仍在响应中且返回状态为 `pending` 或 `sent`，而保护快照状态为 `received`，使用保护快照覆盖该行的状态及签收相关字段。
3. 如果列表返回状态已经是 `received` 或更后阶段，使用列表返回值，不做覆盖。
4. 保护仅允许 `pending`/`sent` 到 `received`，不处理其他状态组合，避免隐藏真实的后续状态或改变状态机语义。

该方案把状态写接口的成功响应视为本次操作的权威写入结果，同时仍刷新列表中的其他字段、分页总数、设备型号和状态统计。

## 数据流

1. `saveReceivedParts` 保存配件明细。
2. `confirmReceivedParts` 记录配件签收人和签收时间。
3. `confirmInboundArrival` 或 `updateOrderStatus` 把符合条件的工单推进为 `received`。
4. PC 页面立即把第三步返回的工单快照应用到详情和当前列表行。
5. PC 页面请求最新工单列表。
6. 仅当同一行短暂返回 `pending`/`sent` 时，用第三步的 `received` 快照阻止状态回退。
7. 刷新状态统计；关闭详情抽屉后列表保持“已签收”。

## 并发与边界

- 本次保护不修改通用刷新函数的默认行为，其他业务操作不传保护快照。
- 若签收后的列表请求失败，已有详情和列表快照仍保留，页面显示现有的部分成功警告。
- 若状态同步接口失败，只保留配件签收结果，不伪造 `received` 状态。
- 若列表返回 `inspecting`、`fixing`、`shipped`、`completed` 或 `cancelled`，认为服务端数据更新，绝不回退到 `received`。
- 若当前筛选条件排除了已签收工单，不把保护快照重新插回列表。

## 验证

### 定向检查

增加静态检查，验证：

- 快照保护是 `loadOrders` 的可选参数，默认不影响其他调用。
- 只有签收状态同步成功路径传入保护快照。
- 只阻止 `pending`/`sent` 覆盖 `received`。
- 响应中没有目标工单时不会重新插入。

### 本地 mock

本地 mock 增加可重复场景：状态写接口已返回 `received`，紧接着第一次 `getAdminOrderList` 故意返回该工单写入前的 `sent` 快照，后续列表请求再返回 `received`。

### 浏览器验收

使用 Playwright 执行以下流程：

1. 打开运输中工单并进入处理抽屉。
2. 保存并确认配件签收。
3. 验证详情显示“已确认签收”、签收人和签收时间，保存第一张截图。
4. 关闭抽屉，不刷新浏览器。
5. 验证列表同一工单显示“已签收”，保存第二张截图。

截图保存到：

- `pc-admin/output/playwright/receipt-detail-confirmed.png`
- `pc-admin/output/playwright/receipt-list-updated.png`

## 验收标准

- 完成签收后详情和列表均显示最新状态。
- 关闭详情抽屉后无需按 F5。
- 人为模拟第一次列表旧读时，列表仍不回退为“运输中”。
- 所有源码变更均位于 `pc-admin/`。
- 未修改或部署任何云函数，未修改数据库和小程序相关代码。
- PC 后台定向检查和生产构建通过。
